# S1 经济仿真与数值校准

运行日：2026-10-26。工具调用真实领域市场、IPO、公司采购/生产、股东投票及货币账本，固定起点 `2026-01-01T00:00:00Z`；不连接数据库，不修改生产服。

## 复现

```sh
make simulate-economy > /tmp/s1-industry-14d.json
(cd services/game && go run ./cmd/economy-sim -consumables) > /tmp/s1-consumables-costs.json
cmp /tmp/s1-industry-14d.json docs/design/04-seasons/simulation/s1-industry-14d.json

```

固定输入对应 [14 天原始报告](simulation/s1-industry-14d.json) 和 [职业制品成本报告](simulation/s1-consumables-costs.json)。JSON 中所有货币数字为 Basis（除场景输入 `initialPublicGold`），并非 Gold。报告输出顺序固定，当前引擎没有随机行为。CI 已加入上述重跑和字节比对；配方或规则改变时必须同步校准说明及报告。

## 假设与不覆盖范围

- 基准 12 人，增长场景 48 人，14 天。四职业均分；这是合成交易主体，并不模拟玩家上线率、竞价心理或前期到达职业的速度。
- 每人每小时外生提供水/木/石/炭/铁/燧石各 20 单位，库存累积、开放卖盘上限各 100 单位。普通供应价格为水 0.10、木 0.45、石 0.95、炭 1.20、铁 3.20、燧石 2.80 Gold。**这部分供给是实验输入，不是从聚落生产函数推导的平衡预测。**
- 普通场景联盟一次发行 100,000 Gold，全部拨公共采购；主体用事先积存的水按 1 Gold 出售给有限预算公共账户取得启动现金，支付真实 1% 税。之后不再补钱、不保证回购。启动收水价只是试验初始化，不是上线承诺。
- 六家公司同时 IPO，各上限 100,000 股、每股 0.05 Gold，下限 50,000 股，一小时窗口。均分认购舍入产生的未发行尾数不补齐；现实应分阶段引入。
- 每人每天分别需求两种终端包各 2 件，以当天参考价挂持续一日买单，第二天撤余单再挂；成交的终端包被外生消费。**需求不是由个人升级或公司回报自动产生**，故满足需求不证明长期用户留存，也不证明真实市场能吸收这些产量。
- 单公司停产场景第 4 天人为停止该公司并选择相关替代配方，固定原价格/预算，检验断供时剩余链条与停产控制；不会假装替代路线自动盈利。
- `price-recovery-vote` 原料价两倍，第 7 天 +1 小时使用真实提案/快照投票，24 小时后执行两倍售价/预算；消费者从第 8 天 +1 小时接受两倍价格。这是可恢复性测试，**消费者愿意涨价是外生假设**。
- `industrial-consumables` 在同样投票时点批准精密包模式；引擎仍按收益筛选实际采购，只有节约覆盖成本才使用。

## 校准改动

初始试算出现部分下游售价与普通原料成本脱节、批次预算不足和耗材首批负担过重。本次把标准链参考售价调整为 24.5 / 27.5 / 61 / 50.5 / 49.5 / 50.5 Gold，批次成本预算从参考收入 80% 改为 85%，按历史成本核算并将一个公司作业包摊销到五批，而不是全算进首批成本。

早期实验使用即时撤销终端买单，随后改为持续一日订单；该变更会改变成交时机。旧试算与最终报告不应作同条件 A/B 效果宣称。原始生产上限也已修正为“新整批加入后不超过两批”，消除了部分销售后多开一批造成的额外积压。

## 14 天结果

终端消费列是两种包的合计实际成交并消费量。每小时运行账户、托管、股份和总量校验，13 场景合计 4,368 次。

| 场景 | 实际终端消费 | 账本检查次数 | 持有额 = 净发行 |
| --- | ---: | ---: | --- |
| industrial-consumables | 2688 | 336 | 一致 |
| price-recovery-vote | 288 | 336 | 一致 |
| baseline-12 | 672 | 336 | 一致 |
| growth-48 | 2688 | 336 | 一致 |
| demand-collapse | 192 | 336 | 一致 |
| input-price-shock | 0 | 336 | 一致 |
| cash-shortage | 0 | 336 | 一致 |
| outage-alloy | 446 | 336 | 一致 |
| outage-crystal | 446 | 336 | 一致 |
| outage-heavy | 432 | 336 | 一致 |
| outage-control | 432 | 336 | 一致 |
| outage-works | 446 | 336 | 一致 |
| outage-precision | 446 | 336 | 一致 |

基准与增长分别满足合成的 672 / 2,688 件需求。需求在第 4 天消失后，终端只消费 192 件，公司在两批库存上限内停产；没有继续采购烧钱。原料翻倍而经营方案不变时全链停产，不能把它当成仿真失败后用增发掩盖。真实投票调整价格和预算后恢复，最后六天成交 288 件。

现金不足场景只发行 12,000 Gold，上游两家成功，其他 IPO 失败退款，终端无法启动。说明“所有公司同时开服上市”对现金规模敏感；策划应看真实市场和周转资金分批引入。六个单点停产实验都有另一分支继续成交，但损失产量，替代路线未必在旧价格下盈利。模型保留这一取舍，没有无条件替代补货或公共账户托底。

工事包初案每批 2 件，单件成本 37.95 Gold，而现有后勤捐献 80 水 +50 木 +25 石值 54.25 Gold，节省 8% 仅 4.34 Gold。改为每批 20 件，单件成本 3.795 Gold，留下交易税和供需定价的空间；回归测试用实际后勤操作验证节约值，而不是只对照配方常量。

个人二级设施普通投入参考价值 1,492.5 Gold，作业包路线节省普通材料 298.5 Gold；四个重载/精密包参考总价 198 /202 Gold，在这组价格下有选择价值。公司精密包则只在五批普通原料的实际节约覆盖包价时购入，不能因为 UI 勾选了就自动亏损采购。精锻刀具只适用于足够昂贵的重复建设；早期自用未必划算，玩家可选择不消费。恢复、侦察和战争支援包含战术收益，不能用固定金币返还来伪造收益率。

## 订单簿性能检查

在 Apple M1 Pro / darwin arm64 上执行：

```sh
cd services/game
go test ./internal/domain -run '^$' -bench BenchmarkEconomyTickFullOrderBook -benchmem -count=3
```

夹具有 100 个账户、10,000 笔有实物托管的开放卖单和 6 家公司；每次测量推进一分钟并完整校验账本。初次检查发现公司挂售扫描无须复制整个订单簿，移除该复制后，三次结果分别为 1.092 /1.084 /1.083 ms/op，46,320 B/op、332 allocs/op。修改前同夹具为 3.506–5.708 ms/op、约 8.25 MB/op。这里证明避免了重复分配；受本机负载影响，耗时仅作量级参考。

该夹具中的公司缺少完整原料而等待供应，**不代表活跃撮合压力、PostgreSQL 写入吞吐量或生产服可承载玩家数**。公司与市场仍使用同一世界事务及线性订单扫描，扩容前需要另测真实成交频率、全量持久化和长时间离线追赶。

## 回归与验收边界

领域回归覆盖资金守恒、冲突政策、IPO 尾差/退款/重试、二级交易去向、投票快照、不能分掉募资本金、扩建调减/取消、全批采购、五批成本摊销、库存上限、满订单簿继续撤单、全部职业制造资格、耗材效果和无效使用、远征序号、跨季金融权益及夜班燃料。

数据库测试显式使用 `DATABASE_URL_TEST` 指向一次性本地 PostgreSQL，各测试独立 schema，验证并发同政策只记一次、审计失败回滚、机构状态 JSON 往返、旧经济全量/远征读取拒绝。`make test` 的 Go race/vet、前端类型/lint、28 项前端测试及生产构建通过，`make check-arch` 的生成契约及分层检查通过；两份仿真报告重跑后逐字节一致。

浏览器验收使用本地测试账号，真实点击建造→排队→耗材使用→IPO 认购→股东提案/投票→执行暂停生产和新价格；电池使 90 秒探测器制造变为 72 秒。长时 IPO/投票的到期时间由一次性测试库夹具调至当前，仍由正常结算器配售/执行。后台核对准备金、公共采购库存、公司现金和认购托管，完整持有额等于净发行额。没有部署或清除生产数据。

上线前仍需封闭测试观察真实玩家生产组合、耗材购买率、买卖价差、金币集中度、股东参与率和低活跃时的公司现金周转。此报告校准规则及边界，不把合成供需当作实服长期经济已经稳定的证据。
