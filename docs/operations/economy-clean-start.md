# 新经济清档重开与验收

本变更是已决定清档重开的不兼容版本。PR 不执行清档、合并或生产发布。唯一长期部署环境为 production；下述 PostgreSQL 测试仅为一次性本地数据库。

## 上线前

1. 验证本 PR 的确切提交、生成契约和全套测试；发布客户端与后端同一版本。备份旧数据库并记录旧镜像摘要，备份放在受控存储，不进入 Git。
2. 停止旧服务和所有写入/定时任务。准备独立、空的新经济数据库（推荐保留旧数据库以便回滚），记录清档时间及受影响账号范围；不要原地逐个重置玩家。
3. 在空库启动新服务，走现有初始化、管理账号和邀请注册流程。核验经济版本 1、发行/国库/公共账户均为零、没有虚构行情或公司；不要从旧 JSON 复制金币、订单或玩家。旧经济版本被全量状态与远征快速路径同时拒绝为 `economy_restart_required`。
4. 策划通过 SSH 管理隧道先签发明确 ID 的发行政策，再划拨公共采购/财政预算。公共采购必须指定有限数量、价格和商品。普通玩家应先生产挂卖，实际成交后才能得到金币。公共库存后续消耗也需政策记录。
5. 依据真实活跃人口、商品深度与可用金币分阶段引入目录公司，核对募资额、公司周转金和个人剩余购买力。离线仿真中的 100,000 Gold 是试验参数，不是上线默认预算，绝不能复制成按用户自动发钱。
6. 在生产维护窗口内验收：邀请注册→前期发展→零金币建职业设施→制造→公开卖单→公共采购成交→IPO→配售/失败退款。确认公网管理员路径 403；核对完整货币恒等式和追加审计。再开放玩家入口。

## 内容赛季与清档的区别

内容赛季保留货币、公司、股份、IPO 与投票，仅重置个人生产/远征进度，先撤玩家订单再处理季节性实物。单账号重置拒绝有效股份、认购或投票头寸，防止破坏共同账本。内容赛季按钮不能用于此次旧经济切换。

## 回滚

关闭入口并停掉新写入；保存新库快照和交易审计。恢复成对的旧后端/客户端镜像与旧库连接，验证旧版本健康和数据一致性后再开放。不能把旧程序指向新经济库，也不能把新版本运行后的余额复制回旧库。若已开放真实新经济交易，回滚会撤销期间进度，需先由运营确认停服恢复范围并公告；本 PR 不自动执行此操作。

## 可复现验证

```
make gen
# 将生成结果暂存后运行架构检查，避免把未暂存生成文件误判成漂移
make check-arch
DATABASE_URL_TEST=<一次性本地PostgreSQL数据库> make test
make simulate-economy
```

`make simulate-economy` 只运行领域引擎，无数据库/网络配置，输出 JSON 到 stdout。仓库保留固定参数的报告与校准说明。PG 集成测试覆盖同政策并发重试、审计失败回滚、持久化和旧库拒绝；领域测试覆盖 IPO 配售/退款、股权交易、投票快照、分红限制、实际采购、库存上限、满订单簿、耗材真实效果及轮询分片等。既有夜班燃料回归测试继续运行。
